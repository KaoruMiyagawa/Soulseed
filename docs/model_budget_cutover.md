# 统一模型预算：调用路径与切换阻断

本记录是设计与盘点，不表示统一账本或全局硬限额已经实现。不得据此启用真实自主联系。

B0.1a 已新增独立 SQLite 预算内核，接口、迁移 21 和恢复协议见 [model_budget_kernel.md](model_budget_kernel.md)。下表的真实模型入口仍未接入该内核，历史导入和切换屏障仍未实施。

| 入口 | 调用路径 | 当前额度 | 时间与请求标识 | 统一账本覆盖 |
| --- | --- | --- | --- | --- |
| 普通聊天及结构化聊天 | `ChatService` → `OpenAICompatibleAdapter` | `model_daily_request_limit` 可选；通用 JSONL | UTC 日；配置日志时生成请求 UUID | 未覆盖 |
| 既有模型式主动联系 | `AdapterContactGenerator` → 共享模型适配器 | 同普通聊天的通用配置 | 同上 | 未覆盖 |
| 探索 Agent | `reply_action` → 单独构造的模型适配器 | 探索专项限制，默认每日 8；独立探索 JSONL；复制设置时覆盖通用限制 | UTC 日；每次请求 UUID，附 run ID 和步骤 | 未覆盖通用额度 |
| 新自主联系 | `AutonomousContactPipeline` → Mock 草稿 | D2 SQLite 子额度及测试用 Mock 通用额度 | UTC 日；D2 request key | 没有真实模型入口 |
| Shadow | 只读候选与决策 | 无模型请求 | 不适用 | 不适用 |

JSONL `started` 是请求预留记录，不证明供应商接收或收费；`http_started`、`finished` 及 `action_validation` 是同一 ID 的后续审计事件，不应再次扣额。通用日志无配置路径时可能完全没有历史记录；探索日志与通用日志分开，历史数据不足以证明两者从未重复写入同一请求 ID。

未来协调器应在一个 SQLite `BEGIN IMMEDIATE` 事务中按请求 ID 幂等预留全局与适用子额度，跨角色合计全局额度。状态至少应区分 reserved、started、完成、明确失败、outcome_unknown 与明确未发送后释放；started 之后的崩溃或结果未知保守计额，不自动重试。同一事务须检查适用额度与绑定的业务预留；网络请求不得持有事务。UTC 跨日时保留原始预留日，不能释放已开始请求。

切换前需明确旧进程何时停止追加旧 JSONL、导入覆盖的文件集合及可验证的截止点。导入应以请求 ID 去重并在同一事务记录来源、导入边界与校验结果；无法证明完整性、记录损坏或跨文件 ID 冲突时不能假设零消耗，须保守扣额或拒绝当天新自主请求。新旧两个权威不能同时独立接受请求；若要保持服务连续，需先让所有真实调用路径共享可协调的切换屏障，再验证崩溃恢复。当前不具备此屏障，不能从只读快照推算出可安全使用的实时全局余额。

事实审核阶段需要接收预算协调器返回的持久请求 ID 和状态；审核结果需另行绑定角色、草稿摘要、证据内容版本和过期时间。预算通过不构成审核或发送授权。
