# 角色状态驱动的主动社交

网页和桌面版的模型主动联系共用 `AutonomousContact`。桌面 `DesktopContact` 在原有投递事务中只补充 Windows 通知记录；网页使用现有 `ContactScheduler`，启用 `contact_model_generation_enabled` 时调用同一核心，未启用模型生成时保留原有联系流程。桌面继续使用原来的桌面联系循环，不增加第二个发信调度器。

角色已有心情、进行中的活动或已保存兴趣时，每个 UTC 日生成一个 `self_social` 候选。它引用当前角色的已保存生活状态，而不是把兴趣权重当作新发现，也不要求用户消息或探索分享。模型收到当前心情、活动、兴趣、有限记忆及互动上下文，自行选择 `contact` 或 `silent` 并生成正文。原有探索分享和旧闲聊优先，用户拒绝、安静时段、忙碌、暂停、预算和去重规则继续生效；未回复的主动消息仍遵循现有等待规则。

候选经过现有持久化、领取、请求与消息额度预留、事实审核、交接及原会话投递。UTC 日维度的稳定候选键使重启不会重复处理；跨日重建候选时仍需通过现有冷却、未回复和预算检查。事实审核对自然语言的识别是启发式的，并不能保证验证每一种表述。

网页沿用已有模型预算模式：严格预算下，模型请求和自主候选预留在开始请求时关联；旧模式保留原 JSONL 预算策略，并先记录自主联系的持久子额度，不能在请求结果不明时重试。迁移 28 扩展候选、联系来源和审核记录表，并在一个事务中检查外键；桌面升级仍使用现有自动备份机制。请仅在隔离数据库和模拟模型中验证，勿将测试指向用户数据。

`autonomous_contact_pipeline.md` 和 `autonomous_intent_kernel.md` 记录 2.9.0 各阶段的历史约束，不描述当前最终运行路径。
